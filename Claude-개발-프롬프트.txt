너는 이 폴더에서 한국·미국 주식 자동 선별 프로그램을 개발하는 엔지니어다. 동봉된 두 원본 명세(01, 02)와 stock-skill 폴더의 SKILL.md 및 references를 먼저 읽고, 설계 설명에서 멈추지 말고 실행 가능한 프로젝트를 작성하고 검증해라.

가장 중요한 요구사항은 사용자가 관심종목이나 티커를 입력할 필요가 없다는 것이다. 실행하면 양국 시장의 상장 종목 목록을 데이터 공급원에서 수집하고, 시가총액·유동성·가격·수급·재무 조건으로 자동 선별한다. 목록 자체를 직접 관리하거나 고정 종목으로 대체하는 것을 기본 실행 방식으로 삼지 마라. 미국과 한국의 완료 거래일을 각각 확인하고, 실제 스캔 범위와 수집 실패 건수를 표시해라.

Java 17 이상, MariaDB, 웹 대시보드를 사용한다. 운영 환경은 AWS Lightsail Linux로 한다. 프로젝트를 이 폴더 안에 작성하고 기존 자료를 보존해라. Windows에서 빌드와 실행을 재현할 수 있도록 README, 환경 변수 예시, 실행 명령을 제공해라. API 키는 환경 변수로 읽고 로그·저장소에 남기지 마라.

1. 데이터 공급원부터 검증한다. 무료 상장 목록, 시총, 일봉·거래대금, 벤치마크, 수급, 공시·재무, 시장심리 지표의 접근 방식과 한도를 공식 문서와 소량 요청으로 확인한다. 무료 API 키가 필요한 공급원은 발급 및 설정 방법을 적는다. 시장 목록과 일봉을 가져오는 공급원 어댑터를 구현한다. 캐시와 호출 제한을 적용하고 소스별로 실패를 격리한다. 테스트용 자료는 명시적인 데모 실행으로 구분한다.
2. 매집 의심(MAS). 한국은 시총 5조 원 및 최근 20거래일 평균 거래대금 100억 원 이상, 미국은 100억 달러 및 2,000만 달러 이상이다. 20거래일 수익률 +15% 이하, 60거래일 +30% 이하를 모두 적용한다. ETF 및 명세상 제외 종목을 걸러라. 독립 영역 2개 이상의 근거와 필수 재무·공시 검증을 적용하고, 관찰·후보·확인 대기·무효화를 구분해라. 미국 13F/ATS는 간접 자료로 표시한다.
3. 역발상(MSI·OIS). 미국 시총 상위 500개, 한국 KOSPI·KOSDAQ 합산 상위 300개를 기준으로 자동 탐색한다. 시장별 MSI를 각각 산출하고 종목 OIS를 독립 계산해라. 시장 공포에 따른 낙폭과 기업 고유 악재를 구분한다. 원본의 분할 진입·차익실현 기준은 시나리오 및 보고에 사용한다. MAS·MSI·OIS를 합산하지 마라.
4. 각 점수에 산출 항목, 관측값, 적용 기준, 커버리지, 신뢰도, 출처, 기준일, 지연 여부를 붙인다. 누락 항목을 추측하거나 0점으로 채우지 마라. 필수 조건이 미확인이면 확인 대기로 분류한다. 원본의 필터·배점을 적용하고, 스킬에 추가된 초기 계산 규칙은 버전을 기록해라. 소스가 지원하지 않는 항목은 미평가로 남기고 실제 적용 범위를 적어라.
5. MariaDB에 실행 내역, 후보 상태, 점수 근거와 추적 이력을 저장한다. 5·10·20·40·60거래일 추적과 상태 전환 중복 방지를 구현한다. 대시보드에서 시장별 후보, 근거와 반대 근거, 누락 데이터, 기준일, 최근 실행 상태를 볼 수 있게 한다. 장 마감 후 자동 실행을 설정할 수 있도록 하고, 알림은 앱 내에서 확인 가능하게 한다. 분석과 모의 검증 범위로 운영한다.
6. 오프라인에서 후보 자동 선별, 필터 경계값, 결측, 재실행 시 중복 저장 방지, 두 점수 체계의 분리와 추적을 검증한다. 실제 연결이 가능한 공급원은 소량 실데이터로 목록 → 일봉 → 선별 → 저장까지 확인해라. 접근이 막힌 소스는 실패 원인과 필요한 설정을 적고, 검증한 항목만 완료로 보고해라.

7. 모의 자동매매
- 역발상 전략에서 자동 발굴한 후보에 시장심리·펀더멘털·수급·반전 조건을 적용해 로컬 가상 계좌의 주문을 생성한다. 진입은 계획금의 20%·30%·30%·20%로 나누고 각 단계 조건을 확인한다. 청산은 보유 수익률, 시장심리, 투자 가설 훼손 여부를 함께 평가한다. 필수 데이터가 부족하면 주문을 보류하고 사유를 저장한다. MAS는 독립적으로 후보와 성과를 추적한다.
- 확정장 신호는 해당 시장의 다음 거래일 시가에 수수료·슬리피지 가정을 반영해 모의 체결한다. 시가가 확인되지 않거나 거래정지 상태면 체결을 기록하지 않고 사유를 남긴다. 실거래 연결은 범위에서 제외한다.
- 가상 시작금, 종목별 한도, 수수료, 슬리피지는 설정값으로 둔다. 가상 현금, 보유 수량과 평균단가, 주문·체결·보류 내역과 근거, 실현·미실현 손익을 MariaDB에 저장하고 대시보드에 표시한다. KRW와 USD 잔액 및 손익은 통화별로 관리한다.
- 동일 신호를 재처리해도 주문·체결은 한 번만 기록한다. 체결과 잔액·보유량 갱신은 한 트랜잭션으로 처리한다. 오프라인 테스트로 다음 거래일 체결, 데이터 누락 시 보류, 중복 방지, 손익 계산을 확인한다.

8. 모의매매 성과 분석 데이터
- 신호 시점과 모의 체결 시점의 데이터를 분리한다. 신호에는 MSI·OIS와 세부 점수, 진입·청산 단계와 판단 근거, 데이터 커버리지, 전일 종가, 최근 20거래일 평균 거래량·거래대금, 신호일 상대 거래량, ATR과 시장·업종 수익률을 저장한다.
- 체결에는 전일 종가 대비 시가 갭, 기준 시가와 모의 체결가, 수량·비용을 저장한다. 데이터가 제공되면 개장 동시호가 실제 체결량, 모의 체결 직전 확인 가능한 매수·매도 호가와 스프레드, 개장 후 첫 1분·5분 거래량과 거래대금도 각각 저장한다. 모의 주문 수량을 같은 구간의 실제 거래량으로 나눈 참여율에는 분모의 구간을 표시한다.
- 각 관측값에 데이터 기준 시각, 실제 사용 가능 시각, 출처와 관측 구간을 붙인다. 일봉만 있으면 체결일 전체 거래량은 사후 분석용으로 저장하고 개장 체결량·분봉·호가는 결측으로 남긴다. 개장 후 집계값과 당일 종가 등 시가 이후 정보는 시가 주문 결정이나 체결 판정에 사용하지 않는다. 일봉 시가 체결은 유동성 확인이 없는 모의 체결 가정으로 표시한다.
- 체결·미체결·보류 내역, 거래가 없는 날을 포함한 일별 계좌 평가액과 입출금, 시장별 벤치마크, 통합 평가 시 적용 환율을 MariaDB에 저장하고 CSV로 내보낸다. 실행 ID, 백테스트/모의 운용 구분, 전략 버전, 신호·주문·체결 ID로 연결할 수 있게 한다.
- 시장·심리 구간·분할 단계·시가 갭·유동성 구간별 비용 차감 후 성과와 표본 수를 비교할 수 있게 한다. 결과를 바탕으로 규칙을 조정할 때 기존 버전을 보존하고, 조정에 사용하지 않은 기간 또는 이후 모의 운용에서 재검증한다.

9. 카카오톡 모의매매 결과 보고
- 사용자가 연결한 본인 계정의 카카오톡 '나와의 채팅'으로 발송하는 옵션을 구현한다. 카카오 로그인과 talk_message 동의를 사용하고, 공식 REST API의 '나에게 기본 템플릿으로 메시지 발송'을 적용한다. 공식 문서 https://developers.kakao.com/docs/ko/kakaotalk-message/rest-api
- 기본 보고 주기는 각 시장의 장 마감 후 해당 거래일 데이터와 계좌 평가가 확정됐을 때 시장별 1회다. 한국어로 [모의매매] 표시, 시장·현지 기준일, 매수·매도 체결 요약, 미체결·보류 사유, 일별 순손익·누적 수익률·총자산을 표시한다. 거래가 없는 날은 체결 0건으로 기록하고, 데이터 미확정 시 정상 보고로 표시하지 않는다. 시장별 보고 사용 여부를 설정할 수 있게 한다.
- 카카오 연결 및 발송은 사용자가 켜는 옵션으로 둔다. 카카오 개발자 앱 설정, 동의, 테스트 메시지, 연결 해제 절차를 README에 적는다. 토큰은 안전하게 보관하고 갱신하며 키와 토큰을 소스·로그·CSV·메시지에 포함하지 않는다.
- 보고서는 DB에 저장된 모의매매 결과에서 생성한다. 계좌·시장·거래일·보고 유형별 발송 기록을 저장해 재실행 시 중복 발송을 막는다. 응답 유실로 성공 여부가 불명확하면 상태를 남기고 자동 재발송하지 않는다. 발송 실패가 모의 체결·계좌 저장을 방해하지 않게 하고, 대시보드에서 발송 상태와 실패 사유를 확인할 수 있게 한다. 테스트는 모의 응답으로 검증하고 실제 테스트 발송은 사용자가 연결 후 직접 실행할 수 있게 한다.

10. AWS Lightsail 운영 및 MariaDB 전환
- Git으로 소스를 옮기고 Lightsail Linux 인스턴스 한 대에 Java 서비스와 MariaDB를 설치하는 구성을 기본으로 한다. Windows 개발과 Linux 운영의 설정을 분리한다. Linux 설치, 환경 변수, 배포·업데이트·재시작 명령과 systemd 자동 시작 설정을 문서화한다.
- 기존 JDBC 연결, 초기 스키마, 쿼리와 트랜잭션을 검토해 MariaDB에서 동작하도록 전환한다. 스키마 변경은 버전별 마이그레이션으로 관리하고 전용 DB 계정을 사용한다. MariaDB는 루프백에서만 접속하도록 설정하고 Lightsail의 IPv4·IPv6 방화벽에서 DB 포트를 공개하지 않는다. 대시보드는 기본적으로 SSH 터널로 접근한다. 비밀번호와 API 키·카카오 토큰은 서버에 별도로 설정한다.
- 기존 SQLite에 운영 이력이 있으면 원본을 백업한 뒤 후보·신호·모의 주문·체결·계좌 잔액·일별 평가액·보고 발송 이력을 옮긴다. 원본 ID·참조 관계·통화·금액 정밀도·기준 시각을 보존한다. 테이블별 건수, 통화별 잔액과 손익, 대표 주문·체결 관계를 대조한 뒤 전환한다. 이력이 없으면 MariaDB에 신규 스키마를 생성한다.
- 서버를 전환할 때 기존 PC의 예약 실행과 카카오 보고를 정지해 두 환경에서 같은 주문·보고가 처리되지 않게 한다. 양국 거래일 기준의 자동 실행과 재부팅 복구, MariaDB 백업·복원 및 전환 실패 시 복구 절차를 검증한다. 이번 운영 범위는 모의매매이며 AWS 리소스 생성·배포는 사용자가 지정한 서버에서 별도로 진행한다.

완료 후 실제 실행 명령, 대시보드 여는 법, 필요한 API 키, 동작을 확인한 범위와 남은 제한을 한국어로 알려줘.
