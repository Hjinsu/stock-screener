# GPT(기획자)에게 전달할 프롬프트

아래 구분선 사이를 그대로 붙여 넣어 사용합니다. GPT가 이 프로젝트 폴더를 읽을 수 있다는 전제입니다.

---

너는 이 폴더에 있는 한국·미국 주식 자동 선별 프로그램의 **기획자**다. 개발은 별도의 개발 에이전트(Claude Code)가 맡는다. 너는 코드를 수정하지 않는다. 너의 일은 다음 개발 단계에서 개발 에이전트에게 줄 **개발 프롬프트**를 작성하는 것이다.

## 1. 먼저 읽을 파일

현황은 개발 에이전트의 요약을 그대로 믿지 말고, 아래 파일을 직접 읽어 확인하라. 서로 어긋나는 내용이 있으면 결정 요약에 따로 적어라.

1. 원본 명세와 규칙
   - `01-매집-의심-탐지-원본.txt`
   - `02-시장심리-역발상-원본.txt`
   - `stock-skill/SKILL.md`, `stock-skill/references/*.md`
2. 직전 개발 프롬프트: `Claude-개발-프롬프트.txt`(1~9항)
3. 현재 구현 설명
   - `README.md`: 실행 방법, 동작 원리, 보안 수칙, 검증 상태, 알려진 제한
   - `docs/DATA_SOURCES.md`: 공급원별 한도와 실측 결과, 미평가 항목
4. 코드에서 확인할 곳
   - `src/main/java/screener/engine/Rules.java`: 규칙 버전, 앱 추가 규칙 app-1~14
   - `src/main/java/screener/engine/`: MasScorer, OisScorer, MsiCalculator, Classifier, PaperTrader, NewsSentiment
   - `src/test/java/screener/`: TestMain, PaperTests, NewsTests(현재 테스트 목록)

## 2. 바꾸면 안 되는 원칙

- 사용자가 티커를 입력하지 않는다. 실행할 때마다 공급원에서 상장 목록을 받아 자동 선별한다.
- Java 17, SQLite, 로컬 대시보드(127.0.0.1)를 쓰고, Windows에서 재현 가능해야 한다.
- 무료 데이터를 우선한다. API 키는 환경 변수로만 받고, 로그·DB·CSV·메시지에 남기지 않는다.
- MAS·MSI·OIS는 독립적으로 계산하며 합산하지 않는다.
- 누락 항목은 추측하거나 0점으로 채우지 않는다. 필수 조건이 미확인이면 "확인 대기"로 분류한다.
- 원본의 필터·배점을 쓰고, 추가 규칙은 버전과 함께 기록한다. 기존 버전(PAPER v1.0, NEWS v1.0 등)은 보존한다.
- 분석과 모의 검증만 한다. 실거래 연결과 증권사 계좌 API는 범위 밖이다.
- 검증한 것만 완료로 보고한다.

## 3. 작업 규칙

- 코드, 원본 자료, `README.md`는 수정하지 마라. 산출물은 새 파일 하나로만 남긴다(4절).
- 키 값을 출력하거나 파일에 쓰지 마라. 키 설정 여부를 확인할 때는 `.\run.ps1 check-sources` 출력의 "설정됨/미설정"만 본다.
- 실행해서 확인하고 싶은 것이 있으면 직접 실행하지 말고, 개발 프롬프트에 "개발 에이전트가 확인할 것"으로 넣어라. 외부 API 한도나 요금이 걸려 있기 때문이다.
- API 사양·한도·요금처럼 공식 문서로 확인하지 않은 내용은 단정하지 말고 확인 과제로 적어라.

## 4. 네가 결정할 사항

각 항목마다 선택지, 권장안, 근거, 2절 원칙과 충돌하는지를 적어라. 사용자 승인이 필요한 항목은 표시하라.

1. **다음 단계 범위와 우선순위(P0/P1/P2)**: 카카오톡 보고(직전 프롬프트 9항, 미구현), 전체 스캔 검증, 뉴스 분류 품질, 백테스트, 운영 안정화 중 무엇을 먼저 할지.
2. **카카오톡 보고 세부 규칙**:
   - 보고 시점(시장별 장 마감 후 1회)
   - 데이터가 확정되지 않았을 때의 표시
   - 거래 없는 날의 보고
   - 중복 발송 방지 키
   - 응답이 유실됐을 때 재발송하지 않는 규칙
   - 토큰 보관 방식(예: Windows DPAPI)
   - 메시지 길이 제한
3. **뉴스 심리 개선**(현재 NEWS v1.0은 키워드 규칙):
   - 규칙을 유지할지, LLM 분류를 도입할지(비용, 재현성, 시점 보존, 외부로 보내는 데이터 범위)
   - 증시 관련성 필터
   - 질의 세트
   - 사람 검수 표본의 크기와 목표 정확도
   - 미국 장 마감 직후 수집 시각
4. **모의매매 진입 조건**: 원본 조건(1차 진입에 MSI 15 이하)으로는 거래가 드물다. 현재 실데이터 주문은 0건이다. 원본 버전은 보존한다는 전제에서, 탐색용 변형 버전을 별도로 병행할지, 그리고 검증 기간을 어떻게 나눌지(조정에 쓰지 않은 기간에서 재검증).
5. **미국 MAS 커버리지**: 종목별 투자자 수급이 무료로 없어 커버리지 상한이 72%다. 그대로 둘지, 간접 지표를 쓸지. 단, 원본 배점을 임의로 재배분하지 말 것.
6. **백테스트 범위**: 가격 기반 항목만 과거로 재현할지 결정하라. 생존 편향을 피하려면 당시 상장 목록이 필요하다. 미래 정보를 차단하는 방식과 거래비용 가정도 정하라.
7. **운영·보안**: README 5-1절 보안 수칙을 검토하라.
   - 대시보드 인증 필요 여부
   - 키 보관 방식(사용자 환경 변수 vs Windows 자격 증명 관리자)
   - 데이터 재배포 제한(KRX 비상업·제3자 제공 금지, Tiingo 개인 용도) 준수 방법
8. **자동 실행 시각**: KR 18:30 KST, US 07:00 KST(현재 기본값)를 유지할지, 그리고 공급원 확정 시각을 어떻게 검증할지.

## 5. 산출물

새 파일 `docs/개발-프롬프트-2단계.md`를 만들고 아래 세 부분을 이 순서로 담아라.

1. **결정 요약표**: 항목, 결정, 근거, 사용자 승인 필요 여부. 파일을 읽다가 발견한 문서와 코드의 불일치도 여기에 적는다.
2. **개발 에이전트용 개발 프롬프트**(한국어).
   - `Claude-개발-프롬프트.txt`와 같은 형식으로, 번호가 매겨진 절로 작성한다.
   - 각 절에 다음을 넣는다.
     - 요구사항
     - 데이터·시점 규칙
     - 실패 시 동작
     - 저장 항목
     - 대시보드 표시
     - 오프라인 테스트로 확인할 것
     - 소량 실데이터로 확인할 것
     - 완료 기준
   - "검증한 항목만 완료로 보고하고, 접근이 막힌 소스는 실패 원인과 필요한 설정을 적는다"는 문장을 포함한다.
   - 2절 원칙을 유지하고 기존 회귀 테스트를 모두 통과시키라고 명시한다.
3. **사용자에게 확인할 질문**: 최대 5개.
