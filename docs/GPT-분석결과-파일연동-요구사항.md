# GPT 분석 결과 파일 연동

기존 개발을 이어가면서 GPT가 원본 명세 두 개에 따라 수집·분석한 한국·미국 주식 후보를 프로그램에서 읽는 기능을 추가한다. 첫 버전은 수동 파일 전달과 외부 분석 화면을 제공한다. 기존 수집기와 점수 엔진은 독립적으로 운용한다.

## 파일 규격 v1

UTF-8 JSON 한 파일은 시장 하나의 완료 거래일 분석을 담는다.

- 공통 필수 필드: schema_version(정수 1), report_id(고유 문자열), market(KR 또는 US), session_date(현지 거래일 YYYY-MM-DD), generated_at(타임존 포함 ISO 8601), rules_version, scan_scope(대상 범위, 조회 수, 실패 수), sources(출처 목록), market_sentiment, accumulation_candidates, contrarian_candidates.
- market_sentiment에는 해당 시장 MSI의 score, coverage_pct, status, 관측 근거, 누락 항목을 저장한다. 후보 목록은 각각 MAS 또는 OIS 결과로 구분한다. 후보에는 ticker(문자열, 한국 티커의 앞자리 0 보존), name, score, coverage_pct, status, 근거, 반대 근거, 누락 항목을 담는다.
- 수치 근거에는 지표명, 값, 단위, 관측 시각과 실제 사용 가능 시각, 출처 식별자를 붙인다. 시장 전수 탐색을 하지 못하면 조회한 범위를 적는다. 산출 불가 점수는 null을 쓰고, 후보가 없는 경우 빈 배열과 함께 자료 부족인지 조건 충족 종목이 없는지 보고한다.
- Claude는 세부 필드의 JSON Schema와 유효한 예시 JSON을 제공한다. 규격이 확정되면 GPT 결과 생성 시 그 스키마를 사용한다.

## 프로그램에서 읽기

- 대시보드에서 JSON을 직접 선택해 가져오는 기능을 먼저 구현한다. 서버에서 지정 폴더를 읽는 방식이 필요해지면 동일한 검증 경로를 사용한다. 서버까지의 파일 전송은 사용자가 수행하거나 별도 연결을 구성한다.
- 필수 필드·점수 범위·시장과 날짜·규칙 버전·미래 시각을 검증한다. 같은 report_id와 동일 파일을 다시 받으면 한 번만 저장한다. 같은 ID의 내용이 다르면 충돌로 표시한다. 검증 실패 시 일부만 저장하지 않고 오류 이유를 표시한다. 오래된 파일은 해당 과거 거래일 결과로 표시한다.
- MariaDB에는 외부 분석 보고서와 내부 결과의 출처가 드러나도록 저장하고, 대시보드에서 시장심리·두 후보 목록·근거를 읽을 수 있게 한다. 외부 보고서 점수는 초기에는 분석 참고용이다. 가상 주문을 생성하는 입력으로 연결하는 경우는 별도 검증 및 요구사항으로 다룬다.
- 정상 가져오기, 중복, 잘못된 파일, 결측 점수, 후보 0건을 오프라인에서 검증한다. 기존 앱의 분석 기능을 통해 외부 분석 데이터가 주문으로 이어지지 않는지 확인한다.

GPT 분석은 요청 시 이용할 수 있는 데이터로 파일을 만든다. 정기 생성과 Lightsail 전송은 별도 실행 일정 및 연결이 마련된 뒤에 운영한다.
