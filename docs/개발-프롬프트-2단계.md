# Claude Code 2단계 개발 프롬프트

기획 문서 2절의 SQLite·Windows 전제는 로컬 기존 구현 설명으로 해석한다. 운영 기준은 최신 개발 프롬프트 10항의 Lightsail Linux·MariaDB이며 Windows에서 개발과 회귀 검증을 재현할 수 있게 한다. README에는 뉴스 심리가 미평가라는 설명과 NAVER 뉴스 소량 검증 기록이 함께 있다. 현재 구현은 뉴스 대체 지표이며 커뮤니티 심리는 미수집이다. README의 미국 MAS 최대 72%는 보고된 값이므로 코드와 실제 배점에서 다시 확인한다. 25개 테스트 통과와 실데이터 주문 0건은 README 기록이며 이번 기획에서 재실행하지 않았다. JSON 가져오기는 후속 범위다.

## Claude Code에 전달할 지시

원본 명세 두 개, 기존 개발 프롬프트 1~10항, README, 공급원 문서와 현재 코드를 읽고 구현 상태를 대조한다. 아래 우선순위로 기존 개발을 이어간다. 관심종목 없이 자동 선별하며, MAS·MSI·OIS를 독립 계산한다. 필수 결측은 확인 대기로 둔다. 거래 범위는 모의매매다. 각 항목은 관련 실행·관측 시각·규칙 버전·실패 사유를 저장하고 대시보드 또는 기존 내보내기에서 확인할 수 있게 한다.

1. **P0 운영 흐름 검증.** SQLite 이력이 있으면 백업·이관하고 MariaDB의 건수·잔액·손익을 대조한다. 자동 실행 한 곳만 켜서 중복 주문과 보고를 방지한다. 오프라인에서 이관 재실행·중복·거래 실패 롤백을 검증한다. 소량 실데이터로 양국 목록→일봉→후보/보류→저장→CSV를 확인한 뒤 호출 한도 안에서 시장별 전체 스캔을 검증한다. 스캔 범위, 성공률, 소요 시간, 완료 거래일을 표시한다. 실데이터에서 진입 신호가 없으면 0건과 이유를 기록하고, 체결 경로는 데모에서 검증한다.
2. **P1 카카오톡.** 본인 '나와의 채팅'으로 정상 거래일 평가 확정 후 시장별 1회 발송한다. 휴장일은 생략하고 체결 없는 거래일은 0건으로 보고한다. 재시도 기한까지 데이터가 미확정이면 별도 지연 통지 1회 후 확정 보고가 가능하다. [모의매매]·시장·현지 거래일·체결 수·보류 요약·일별 순손익·누적 수익률·총자산을 담되 기본 텍스트 템플릿 200자 이내에서 핵심 항목을 우선한다. 필수 링크는 허용된 주소를 사용하고 개인 대시보드를 공개하지 않는다. 계좌·시장·거래일·보고 유형을 유일 키로 쓰고 대기·성공·실패·결과 불명 상태를 보관한다. 응답 유실이면 자동 재발송하지 않는다. 토큰은 비밀 저장소에 보관하고 갱신한다. 길이·중복·타임아웃을 모의 응답으로 테스트하고 실제 발송은 사용자 연결 뒤 직접 실행할 수 있게 한다. https://developers.kakao.com/docs/ko/message-template/default
3. **P1 뉴스 심리.** NEWS v1.0을 보존하고 v2는 제목·제공 가능한 요약에서 증시·지수·업종 관련성을 먼저 판단한다. 광고·복제·무관 기사·방향이 불명확한 기사를 제외하거나 미분류로 둔다. KR은 코스피·코스닥·외국인 수급·업종, US는 S&P 500·나스닥·미 국채 금리·VIX 등 시장별 질의를 버전 관리한다. 직전 거래일 마감부터 기준 거래일 마감까지의 기사를 사용하고 발행·수집 시각과 검색창 커버리지를 기록한다. 미국 뉴스 첫 수집은 거래소 실제 마감 +30분으로 설정한다. 뉴스 점수를 커뮤니티 심리로 표시하지 않는다. 시장별 100건 이상을 날짜·출처·심리 범주가 섞이도록 사람이 검수한다. 초기 통과 목표는 관련성 정밀도 85%, 평가 가능한 기사 방향(부정·중립·긍정) 일치율 75%이며 7단계 혼동과 미분류율도 보고한다. 목표 미달이면 v2를 참고용으로 유지한다. 오프라인에서는 무관 기사·복제·경계 시각을, 소량 실데이터에서는 출처 수와 질의별 누락을 확인한다.
4. **P2 진입 변형.** 원본 1차 MSI ≤15와 분할 20/30/30/20을 유지한다. 별도 실험 계좌에서 1차 MSI ≤20만 변경하고 OIS·재무·반전·리스크·체결 가정을 동일하게 둔다. 버전과 원본 대비 차이를 저장한다. 누락·검증 불가 신호는 보류한다. 같은 신호가 원본 계좌에 영향을 주지 않는지 테스트한다. 역사 자료가 충분하면 시간순 60/20/20으로 개발·검증·최종 평가를 나누고 경계를 넘는 포지션을 비교에서 일관되게 처리한다. 부족하면 실험 설정을 먼저 고정하고 이후 모의 운용을 비교한다. 완료 거래 건수·순수익·낙폭을 같이 보고하고 표본 부족이면 결론을 유보한다.
5. **P0 미국 MAS.** 직접 수급 배점은 미평가로 유지하고 기존 배점을 재배분하지 않는다. 관측 배점·확인 점수·가능 범위·결측 이유를 표시하고 72% 상한의 산출 근거를 코드에서 확인한다. 13F·ATS는 확보 가능할 때 공개 시각과 지연을 표시한 참고 자료로 둔다. 가격·거래량을 수급 점수에 중복 반영하지 않는다. 오프라인에서 점수 범위를, 소량 실데이터에서 결측과 필수 필터 표시를 검증한다.
6. **P2 백테스트.** 가격 기반 신호와 이후 5/10/20/40/60거래일 성과부터 재현한다. 당시 상장·상장폐지 목록이 없으면 현존 표본 탐색이라고 명시하고 전수 전략 수익률로 해석하지 않는다. 공시·뉴스는 신호 시각 이전에 사용 가능했던 기록만 쓰고, 다음 거래일 시가에 체결하며 개장 이후 거래량으로 시가 체결을 판정하지 않는다. 수수료는 시장별 설정값, 슬리피지는 편도 5/10/25bp 민감도 시나리오로 비교한다. 가정·기준 데이터·벤치마크·통화·검증 기간을 저장하고 순수익·낙폭·거래 수를 보고한다. 시가 결측과 미래 데이터 차단을 오프라인에서 검증한다.
7. **P0 보안.** Lightsail의 대시보드와 DB는 루프백으로 제한한다. 개인용 대시보드는 SSH 터널로 접근하고 외부 공유 시 별도로 인증과 HTTPS를 설계한다. Linux 서비스 전용 계정과 DB 전용 계정을 사용한다. Linux에서는 서비스 전용 파일 권한 또는 systemd 자격 증명으로 비밀을 전달하고, Windows에서는 개발 시 기존 환경 변수 설정을 유지한다. 갱신되는 카카오 토큰 저장소는 서비스 전용 쓰기 권한으로 제한한다. 로그·캐시·DB 내 분석 자료·CSV·Git에 키가 남지 않는지 검증한다. 공급원별 약관을 확인하고 재배포 권한이 없는 원본은 개인 환경에 보관하며, 카카오에는 계좌 집계 중심으로 보낸다.
8. **P0 자동 실행.** KR 18:30 KST·US 07:00 KST는 본 분석 첫 시도로 유지한다. 미국 뉴스 수집은 3항의 거래소 마감 기준으로 별도 실행한다. 거래소 현지 캘린더로 휴장·단축장·서머타임을 처리한다. 기대 거래일과 실제 확정 봉·핵심 데이터의 기준일이 다르면 해당 거래일을 대기 상태로 남기고 30분 간격으로 최대 3시간 재시도한다. 직전 거래일 결과를 당일 결과로 발송하지 않는다. 시가 체결은 예정 거래일의 시가가 확인되면 처리하고 기존 주문을 중복 실행하지 않는다. 공급원별 최초 정상 시각과 누락을 최소 10거래일 수집한 뒤 기본 시각을 조정할 근거를 제시한다. 휴장·단축장·서머타임·지연·재시작은 오프라인에서 재현한다.

기존 회귀 테스트를 모두 통과시킨다. 검증한 항목만 완료로 보고하고, 접근이 막힌 소스는 실패 원인과 필요한 설정을 적는다.

## 사용자 확인 사항

실제 서버 전환 시 기존 PC 예약 실행의 중지 시점을 정한다. 카카오톡은 계정 연결 후 사용자가 첫 테스트 발송을 실행한다. 실험 버전 승격이나 유료 공급원 도입은 검증 결과와 비용을 보고 별도로 결정한다.
