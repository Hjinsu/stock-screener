# 한국·미국 주식 자동 선별 (분석·모의 검증 전용)

이 프로그램은 실행할 때마다 한국(KOSPI·KOSDAQ)과 미국(NYSE·NASDAQ 등)의 상장 종목 목록을 공급원에서 직접 받아옵니다. 관심종목이나 티커를 입력할 필요가 없습니다. 받아온 종목은 다음 세 체계로 각각 따로 평가합니다.

- **MAS(매집 의심 점수)**: 원본 명세 01 기준
- **MSI(시장심리지수)·OIS(종목 투자기회 점수)**: 원본 명세 02 기준

세 점수는 합산하지 않습니다. 결과는 DB에 저장되고 웹 대시보드에서 봅니다. 운영 서버(AWS Lightsail Linux)는 **MariaDB**를 쓰고, Windows 개발 PC는 기본으로 SQLite 파일을 씁니다. 운영 절차는 [docs/DEPLOY_LIGHTSAIL.md](docs/DEPLOY_LIGHTSAIL.md)에 있습니다. 역발상(OIS) 후보로는 로컬 가상 계좌에서 모의매매를 합니다. **실제 주문·환전·자금 이동 기능은 없습니다.** 점수는 확률이나 예상 수익률이 아닙니다.

원본 자료(`01-…`, `02-…`, `Claude-개발-프롬프트.txt`, `stock-skill/`)는 수정하지 않고 그대로 두었습니다.

## 1. 준비

- Windows 10/11, JDK 17 이상(`java -version`으로 확인), 인터넷 연결
- Maven·Gradle은 필요 없습니다. `build.ps1`(Linux는 `deploy/linux/build.sh`)이 Maven Central에서 SQLite JDBC·MariaDB JDBC·slf4j를 내려받고, 소스에 고정한 SHA-256과 대조합니다.

### API 키 설정

권장 방식은 키 입력 스크립트입니다. 입력값이 화면에 표시되지 않고, 사용자 환경 변수로 저장됩니다. 저장 후에는 터미널과 대시보드를 다시 시작하세요.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\set-krx-key.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\set-dart-key.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\set-sec-useragent.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\set-naver-key.ps1     # 선택: 뉴스 심리
powershell -ExecutionPolicy Bypass -File .\scripts\set-ecos-key.ps1      # 선택: 공식 환율
powershell -ExecutionPolicy Bypass -File .\scripts\set-tiingo-key.ps1    # 선택
powershell -ExecutionPolicy Bypass -File .\scripts\set-fmp-key.ps1       # 선택
.\run.ps1 check-sources                                                     # 설정 확인(값은 출력하지 않음)
```

대신 `Copy-Item env.example.ps1 env.local.ps1`로 복사해 값을 채워도 됩니다. `run.ps1`이 자동으로 읽고, 파일은 `.gitignore`에 포함됩니다. 다만 평문 파일이므로 스크립트 방식을 권장합니다.

| 변수 | 필수 | 발급·설정 |
|---|---|---|
| `KRX_API_KEY` | 한국 필수 | https://openapi.krx.co.kr 회원가입 → API 인증키 신청 → 서비스별 **이용 신청·승인**이 필요합니다. 신청할 서비스: 주식 › 유가증권 일별매매정보, 코스닥 일별매매정보 / 지수 › KOSPI 시리즈 일별시세정보, KOSDAQ 시리즈 일별시세정보. 키당 일 10,000회, 비상업적 이용, 화면에 "한국거래소 통계정보" 출처 표시 조건이 있습니다. |
| `DART_API_KEY` | 한국 필수 | https://opendart.fss.or.kr → 인증키 신청. 1인 1키입니다. |
| `SEC_USER_AGENT` | 미국 필수 | 키가 아니라 SEC 정책상 요구되는 User-Agent 문자열입니다. 형식은 `앱이름/버전 본인이메일`이며, SEC에만 전송됩니다. |
| `TIINGO_API_KEY` | 선택 | https://www.tiingo.com → API Token. 전 종목 최근가를 1회 호출로 받아 미국 예비 시총을 계산합니다. 무료 한도는 시간당 50회, 일 1,000회입니다. 없으면 Yahoo spark로 대체합니다. |
| `FMP_API_KEY` | 선택 | ADR·다중 클래스 종목의 시총을 보조로 확인합니다. 한도를 초과하면(HTTP 429) 그 실행에서 즉시 중단합니다. |
| `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` | 선택 | **NAVER API HUB** 검색 API 인증 정보입니다. 네이버 클라우드 플랫폼 콘솔 → NAVER API HUB → Application → 인증 정보에서 발급합니다. MSI '뉴스·커뮤니티'(25%) 영역에 씁니다. 기존 developers.naver.com 키는 HUB에서 쓸 수 없습니다(실측 HTTP 401). 없으면 이 영역은 미평가입니다. |
| `ECOS_API_KEY` | 선택 | 한국은행 ECOS의 원/미국달러 매매기준율(731Y001)입니다. 통합 평가 환율에 쓰며, 없으면 Yahoo KRW=X(비공식)로 대체합니다. |

필요 없는 키도 있습니다. `FRED_API_KEY`는 현재 쓰지 않습니다(VIX는 Cboe 공식 CSV 사용). **토스증권 등 실계좌 API 키는 이 프로젝트에 필요 없고, 넣지 않기를 권장합니다.** 실거래 연결은 범위 밖이고, 주문 권한이 있을 수 있는 키를 불필요하게 보관하게 되기 때문입니다.

키는 환경 변수에서만 읽습니다. 로그·DB·캐시·CSV에는 기록하지 않으며, 로그에서는 `***`로 마스킹합니다. 공급원별 한도와 검증 결과는 [docs/DATA_SOURCES.md](docs/DATA_SOURCES.md)에 정리했습니다.

## 2. 빌드와 실행 명령

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1          # 의존성 검증 → 컴파일 → screener.jar → 오프라인 테스트
powershell -ExecutionPolicy Bypass -File .\build.ps1 -SkipTests

.\run.ps1 check-sources                 # 공급원별 소량 요청 점검(키 값은 출력하지 않음)
.\run.ps1 run                           # 한국·미국 전체 자동 선별 + 모의매매
.\run.ps1 run --market KR               # 시장 하나만
.\run.ps1 run --market US --limit 60    # 검증용 소량 실행(시총 상위 60개만, 전체 스캔 아님)
.\run.ps1 demo                          # 합성 데이터 데모(별도 DB data\demo.db, 70거래일 순차 실행)
.\run.ps1 serve                         # 대시보드 + 장 마감 후 자동 실행
.\run.ps1 serve --demo                  # 데모 DB 대시보드
.\run.ps1 export-csv                    # 성과 분석 CSV → data\export\<날짜>\
.\run.ps1 export-csv --demo --out D:\csv
.\run.ps1 db-status                     # DB 종류·스키마 버전·인스턴스 역할·테이블 건수
.\run.ps1 sqlite-snapshot --out .\snap.db   # 서버 이관용 일관 사본(-wal 포함)
.\run.ps1 retire-local [--undo]         # 서버 이관 후 PC 실행 중지(또는 복귀)
```

PowerShell 실행 정책 때문에 `.\run.ps1`이 막히면 `powershell -ExecutionPolicy Bypass -File .\run.ps1 run`처럼 실행하세요.

- **첫 실행 시간**: 한국은 KRX 140영업일 이력을 일자당 2회 호출로 받아 DB에 저장하므로 오래 걸립니다(호출당 약 4초). 이후에는 새 일자만 받습니다. 미국 전체 실행은 Yahoo 일봉 약 수백 종목, SEC 업종 조회 등으로 수 분이 걸립니다.
- **중복 실행 방지**: `data\run.lock` 파일 잠금으로 막습니다.
- **종료 코드**: 0=정상, 2=시장 실패, 3=다른 실행 중.

### 장 마감 후 자동 실행

- **대시보드 실행 중**: 설정 탭에서 켭니다. 기본 시각은 KR 평일 18:30 KST, US 화~토 07:00 KST입니다.
- **대시보드 없이**: 아래처럼 Windows 작업 스케줄러에 등록합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\register-task.ps1 -KrTime 18:30 -UsTime 07:00
powershell -ExecutionPolicy Bypass -File .\scripts\register-task.ps1 -Remove
```

공급원 자료가 아직 확정되지 않았으면 직전 영업일을 기준일로 처리하고, 그 사유를 실행 기록에 남깁니다. 예를 들어 KRX 당일 자료가 아직 없거나, Yahoo가 당일 종목 일봉 종가를 미확정으로 주는 경우입니다.

## 4. 동작 원리 요약

### 자동 선별
1. 상장 목록을 수집합니다. 한국은 KRX 일별매매정보 전 종목, 미국은 Nasdaq Trader Symbol Directory입니다.
2. ETF·우선주·SPAC·워런트·관리/정지·재무상태 플래그·테스트 종목은 유형 단계에서 제외합니다.
3. 시총을 정합니다. 한국은 KRX 값을 쓰고, 미국은 SEC 발행주식수 × 완료일 종가(근사)로 계산합니다. ADR·해외 발행사와 거래대금 대비 시총이 비현실적인 종목은 시총 미확인으로 둡니다.
4. 일봉을 받은 뒤 MAS 신규 후보 필터(시총·20일 평균 거래대금·20일 +15% 이하·60일 +30% 이하)를 적용합니다. 이어서 수급(한국)·업종·재무, 점수, 공시 순서로 필수 검증합니다.
5. OIS 유니버스는 미국 시총 상위 500개, 한국 KOSPI·KOSDAQ 합산 상위 300개입니다(`US_OIS_TOP`, `KR_OIS_TOP`).

### 점수 표기
- 모든 항목에 관측값·기준·출처·기준일·지연·대체 여부가 붙습니다. 미평가 항목은 0점이 아니라 "미평가"로 남깁니다.
- 표시 형식은 "확인 S/W점, 커버리지 W%, 가능 범위 S~S+100−W"입니다.
- 커버리지가 70% 미만이거나 필수 재무·공시 검증이 미완료면 "확인 대기"로 분류합니다.
- 원본 배점·필터 위에 스킬의 초기 판정 규칙을 적용하고, 앱에서 추가한 규칙(app-1~12)을 버전과 함께 기록합니다(대시보드 설정 탭).

### 상태 관리
- **MAS 상태**: 관찰(50+)·초기 의심(60+)·강화(70+)·고득점(80+)·매우 강함(90+)·신호 약화·무효화·등록 차단·확인 대기·추적 종료
- **히스테리시스**: 강화 상태에서 67점 이하, 고득점 상태에서 77점 이하로 내려가면 하향합니다. 상향은 단계 하한보다 2점 이상 높을 때만 인정합니다.
- **알림**: 상태가 바뀔 때만 보냅니다. 같은 기준일·유형은 1회, 같은 유형은 10일 내 재알림을 억제합니다.

### 모의 자동매매(원본 02 역발상)
- **진입 대상**: OIS "관심(65+)" 또는 "우선 검토(80+)" 후보
- **분할 진입**: 단계 조건은 OIS 시나리오를 따릅니다.
  - 1차 20%: MSI 15 이하 + 60일 고점 대비 -15% 이상 하락
  - 2차 30%: 투매(하락일 거래량 1.5배 이상)
  - 3차 30%: MSI 5일 개선 + 지수 하락 둔화
  - 4차 20%: 종목·지수가 20일선 회복
- **청산**: +10%(1/3), +15%(잔여의 1/2), MSI 80 이상(1/3), MSI 90 이상(전량), MSI 고점 하락 전환(전량), 투자 가설 훼손(위험 공시·실적 악화, 전량)
- **보류**: MSI·OIS 필수 데이터가 부족하면 주문하지 않고 사유를 저장합니다(`decision=DEFER`).
- **체결**: 확정 종가로 만든 신호를 **해당 시장의 다음 거래일 시가**에 체결합니다.
  - 매수 체결가 = 시가 × (1+슬리피지), 매도 체결가 = 시가 × (1−슬리피지)
  - 수수료·세금은 설정값을 따릅니다. 기본값: KR 수수료 0.015%·매도세 0.18%·슬리피지 10bp, US 0%·5bp
  - 시가가 확인되지 않거나 거래정지(KRX 시가 0)면 체결을 기록하지 않고 미체결 사유만 남깁니다.
  - 다음 거래일은 신호 시점에 추측하지 않고, 실제 지수 달력에서 확인한 뒤 확정합니다.
- **유동성 표시**: 일봉 시가 체결은 **유동성 확인이 없는 모의 체결 가정**이라고 체결 기록에 표시합니다.
  - 체결일 전체 거래량은 사후 분석용으로만 저장합니다. 참여율 분모에는 "체결일 전체 거래량(일봉)"이라고 구간을 표시합니다.
  - 개장 동시호가 체결량·호가·스프레드·1분/5분 거래량은 무료 공급원이 제공하지 않아 결측(NULL)으로 남깁니다.
  - 시가 이후 정보(당일 거래량·종가)는 주문 결정이나 체결 판정에 쓰지 않습니다.
- **계좌 설정**: 가상 시작금(KRW 1억·USD 10만), 종목별 계획금 10%, 종목 한도 15%, 현금 유보 20%. 대시보드 설정 탭에서 바꿀 수 있습니다.
- **기록 방식**:
  - 신호·주문·체결은 자연키(UNIQUE)로 한 번만 기록합니다.
  - 체결과 현금·보유량 갱신은 한 트랜잭션으로 처리합니다.
  - 일별 평가는 원장(체결·입출금)에서 다시 계산하며, 거래가 없는 날도 포함합니다.
  - USD 계좌는 USD/KRW 환율(Yahoo KRW=X)과 그 기준일을 함께 저장합니다.
- **MAS**: 주문을 내지 않고, 독립적으로 후보와 성과만 추적합니다.

### 뉴스 심리(MSI '뉴스·커뮤니티' 영역, NEWS v1.0)

- **창**: 직전 거래일 장 마감부터 기준일 장 마감까지(현지 시각)입니다. 창 이후 기사는 쓰지 않습니다.

- **미평가 조건**: 독립 출처가 20곳 미만이거나, 창 전체를 덮은 질의가 하나도 없으면 미평가입니다. 일부 질의가 창 후반부만 표본으로 잡힌 경우 커버 시간을 기록합니다.
- **시점 보존**: 한 번 확정된 기준일 결과는 다시 수집하지 않습니다. 기사 제목·링크·언론사·단계는 `news_items`에, 일별 요약은 `news_daily`에 저장합니다.
- **한계**: 풍자·반어를 판별하지 못하고, 증시와 무관한 기사가 섞일 수 있습니다. 커뮤니티 게시물은 수집하지 않습니다(디시인사이드·4chan 제외 원칙 유지). 그래서 이 지표는 '대체'로 표시되고 MSI는 '잠정'입니다.

  - v3: 모의매매
  - v4: 뉴스

- **MariaDB 정의**: InnoDB, `utf8mb4_bin`(SQLite와 같은 바이너리 비교·정렬), 키 컬럼은 VARCHAR, 금액·가격은 DOUBLE(SQLite REAL과 비트 동일), 시각은 ISO 문자열 그대로 둡니다.

## 6. 검증 상태 (2026-11-13 기준)

### 오프라인 테스트 — 28개, SQLite·MariaDB 10.11 양쪽 모두 통과
MariaDB로 테스트하려면 다음을 지정합니다. 테스트마다 임시 DB `screener_t_*`를 만들고 끝나면 삭제합니다.
```powershell
$env:SCREENER_TEST_DB_URL='jdbc:mariadb://127.0.0.1:3307/'; $env:SCREENER_TEST_DB_USER='root'; $env:SCREENER_TEST_DB_PASSWORD='…'
java -cp "build\test-classes;build\classes;lib\*" screener.TestMain
```
- 이관: 체크섬 정밀도(1 ulp·정수/실수 구분), 방언 변환, 구버전 SQLite 자동 업그레이드, SQLite→MariaDB PASS·재이관 거부·원본 퇴역(MariaDB 지정 시)
- 후보 자동 선별: 데모 공급자 상장 목록 → 유형 제외 → 필터 → 확인 대기 분류
- 필터 경계값: 시총 5조·거래대금 100억 정확히 통과, 1 미만은 탈락. 20일 +15%·60일 +30% 경계 포함. 미국 근사값 ±10%는 미확정
- 결측 처리: 미평가와 W·가능 범위 반영, 필수 재무 미확인 시 확인 대기
- 위험 처리: 공시 차단·무효화, 장부 레버리지만으로는 차단하지 않음
- 상태 전환: 히스테리시스, 공시 키워드 분류
- MSI: W<75 미산출, 잠정 표시, 동일 구성 변화량
- 재실행 시 중복 저장 없음(추적 종료일 포함), MAS·OIS·MSI 분리
- 5·10·20·40·60거래일 체크포인트와 MFE/MAE 재계산 일치
- 완료일 2차 확인(확정 봉 80% 미만이면 조정)
- 모의매매: 다음 거래일 시가 체결·비용·관측 메타·중복 방지·CSV, 시가 미확인 시 미체결, 데이터 부족 시 보류, +10% 청산 손익과 평가 항등식, KRX 시가 0 처리

- 공급원: `check-sources`에서 16개 공급원 응답을 확인했습니다(NAVER API HUB 뉴스, ECOS 환율 포함). 기존 개발자센터 엔드포인트는 HUB 키로 401입니다.

### 아직 검증하지 못한 항목
- 전체 스캔(상한 없는 `run`): 한국은 최대 300+종목 수급 수집, 미국은 시총 100억 달러 이상 + 상위 500 전체. 소요 시간과 실패율을 확인하지 못했습니다.

- 자동 실행: 대시보드 스케줄러와 `register-task.ps1` 등록을 실제 장 마감 시각에 돌려 보지 않았습니다.
- KRX 당일 자료가 몇 시에 반영되는지 확인하지 못했습니다.

### MariaDB·이관 검증(2026-11-13, 로컬 MariaDB 10.11.10, 127.0.0.1:3307, 기존 3306 서버와 분리)
- **한국 실데이터 SQLite 이관**: 마이그레이션 도입 이전 형식이고 KRX 일봉 387,276행을 포함합니다. 24개 테이블의 건수·내용 체크섬이 모두 일치해 PASS(8.6초)였습니다. 재이관은 거부(종료 코드 1)되고, 퇴역 원본의 실행도 거부(종료 코드 3)됩니다.
- **데모 이관**: 모의 체결 5건·일별 평가 140행 모두 PASS입니다. 통화별 잔액(KRW 100,000,000 / USD 98,079.4197886583), 실현손익·최신 평가액·입출금, 대표 신호→주문→체결 5건이 일치하고, 참조 무결성 위반은 0건입니다.
- **MariaDB 실행**: 한국 소량 실행 결과가 SQLite 실행과 같았습니다(MSI 47.4, 같은 기준일 재실행 시 점수 행 증가 없음). 대시보드 API·CSV도 MariaDB에서 동작했습니다.
- **백업·복원**: `mariadb-dump`(16.6MB gzip)를 별도 DB에 복원한 뒤 25개 테이블의 `CHECKSUM TABLE`이 모두 일치했습니다.
- **Linux 스크립트**: 7개 모두 `bash -n` 문법 검사만 통과했습니다. systemd·Lightsail 실제 동작은 검증하지 않았습니다(docs/DEPLOY_LIGHTSAIL.md 8장 체크리스트).

## 7. 알려진 제한
- **미평가 항목**: 미국 종목별 투자자 순매수(MAS 25점·OIS 8점), 한국 연기금 세부 수급(5점), 사업 경쟁력·가이던스(정성), 뉴스·커뮤니티 심리(MSI 25%)는 무료 공급원이 없어 미평가입니다. 그래서 미국 MAS 커버리지는 최대 72%이고, MSI는 항상 "잠정"입니다.
